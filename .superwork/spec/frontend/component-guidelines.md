# React 组件规范

## Purpose

约束 `apps/web` 内组件的职责、可访问性和渲染边界。

## Rules

- 所有用户主动操作的成功与失败结果统一通过应用根级 Sonner toast 展示，Feature 组件不得渲染动作结果成功文案或错误块，也不得直接导入 Sonner；失败后仍应保留可重试的输入、草稿和必要业务状态。查询加载错误、表单输入校验、Timeline/Tool 领域错误和待审批状态不属于动作结果，继续在所属视图表达。Codex 与 Git 动作失败的 toast 必须原样显示 Client 收到的底层错误文本。
- `PairingGate` 必须位于 Router 和全部业务 Provider 之外；LAN 未认证时只显示品牌、访问密码表单、提交、通用错误与重试状态，不挂载 Project、Settings、Composer 或 Event Runtime，也不创建独立登录路由。
- 访问密码表单必须提供可访问 Label、提交状态和键盘焦点；密码只保留在表单局部状态。LAN 设置页必须提供明确注销动作，并复用顶层 Access 清理边界。
- 每个组件只承担一个可描述的界面职责，紧凑工作台界面避免装饰性嵌套卡片。
- 会触发网络 Mutation、宿主应用或持久化副作用的按钮和表单必须在事件入口同步单飞，直到当前 Promise 成功或失败后再允许执行；不得只依赖下一次 React 渲染的 `isPending`，也不得使用固定毫秒 debounce。锁按 Project、Task 或请求身份隔离，切换作用域不能被旧请求阻塞；失败重试继续遵循原 `Idempotency-Key` 规则。
- 左栏添加 Project 的前台完成边界只到注册响应；成功后必须立即用响应更新项目缓存并关闭目录选择器，不得等待或广域失效 Task、Snapshot、Git 等无关查询，也不得改变当前 Project/Task 路由。新 Project 的 Task 数据仅在侧栏展开等真实消费发生后按需读取。
- Inspector 的“项目/上下文”页签只允许由用户点击切换；后台终端、子代理、Task 运行态及 Project/Task 导航变化不得自动改变当前页签。Inspector Project 文件树必须以默认展开的项目根文件夹名称开头，不在树外重复显示“项目文件”标题；根节点展开状态只属于界面，不得作为相对目录路径发起文件查询。项目根节点 hover 或键盘聚焦时必须显示带 Tooltip 的刷新图标，单次操作重新读取当前根目录、全部已展开目录和 Project Git 状态，允许重新识别 Git 与非 Git Project，刷新期间保持可见并同步单飞。文件与目录节点 hover 或键盘聚焦时必须在行尾显示 `Ellipsis` 操作按钮，点击后打开与右键一致的菜单，菜单打开期间保持按钮可见；右键目标立即进入文件树选中高亮态。文件菜单顶层依次提供“复制名称”“复制路径”“打开”“引用”，目录菜单只提供前三项；“复制路径”必须把 Project 根目录与文件树相对路径组合为宿主绝对路径。只有“打开”使用二级菜单并复用同一宿主应用目录，文件菜单额外提供系统默认应用。项目根节点打开请求必须省略相对 `path`，由 Server 解析为项目根目录；项目根节点和所有目录均不得生成引用入口。“引用”必须把普通文件作为现有 `@path` Token 添加到当前 Project/Task Composer 草稿并聚焦输入框。菜单中的打开命令不修改中栏保存的默认应用。菜单必须脱离滚动容器裁剪并限制在视口内，打开后聚焦首项，支持级联键盘导航、Escape 和外部点击关闭，请求期间禁用重复操作。
- 中栏顶部右侧必须常驻项目快捷打开组合控件：主按钮使用全局 `defaultOpenAppId`，默认项不可用时回退到首个可打开目录的宿主应用；菜单选择其他应用时直接打开当前项目根目录，且不修改全局默认值。项目根目录请求必须省略 `path`，目录入口不得提供 `system-default`；能力检测或打开请求期间禁用不可执行操作。桌面组合按钮可见高度固定为 `24px`，主按钮图标为 `14px`，下拉应用图标与文件树菜单统一为 `16px`；移动端可隐藏按钮文字但必须保留可访问名称和至少 `44px` 触控目标。
- Inspector 的 MCP 区域必须用图标和文本共同展示 `starting | ready | failed | cancelled`；成功项展示工具数量、认证状态和版本，失败项展示失败原因并允许展开脱敏错误日志，不得渲染 Provider `serverInfo.description` 作为额外底部文案。清单 Query 读取失败时必须直接展示 Codex 原始错误消息、统一错误码和 HTTP 状态，不得只显示 `502`；手动重试失败只通过根级 toast 展示同一原始消息，不得在栏目内叠加动作错误。手动重试使用带 Tooltip 的图标按钮，提交或刷新期间禁用且显示进行中状态。
- 中栏 Composer 底部必须在当前分支控件旁常驻可访问的 Git 历史图标，按钮高度、图标尺寸和交互态与同一区域控件一致；Inspector 不得重复提供该入口。Git 历史 UI 随工作台静态闭包加载，但 Sheet 和历史 Query 仅在点击后挂载；标题区必须展示活动仓库 Tab 自身的当前分支，无分支时显示 `detached HEAD`，未加载时显示明确读取状态且不得沿用上一仓库分支；关闭时清理当前 Project 的历史、提交文件和 Diff 缓存并恢复入口焦点，确保再次打开时读取当前检出的 `HEAD`。根仓库直接展示提交列表，聚合模式使用可键盘导航的横向 Tab 分开展示直属子仓库，并在单次打开期间按仓库独立缓存分页结果、分支和已访问面板实例，切换时不得重置抽屉结构或已加载列表。每页默认展示最近 `20` 条；继续加载操作必须位于滚动内容的最后一项之后，存在 `nextCursor` 时显示加载按钮，否则在非空列表末尾明确提示已加载全部提交。提交行必须可点击，并在保持历史 Sheet 挂载的同时打开独立共享文件审核 Dialog；关闭审核只关闭 Dialog，并保留仓库 Tab、分页和滚动状态。提交文件每页加载 `100` 条，单文件 Diff 只在选中后动态读取和挂载。Sheet 与审核 Dialog 必须覆盖加载、失败重试、空状态、Diff 截断提示，以及 `320px` 窄屏无横向溢出和至少 `44px` 的主要触控目标。
- 中栏 Composer 的根仓库分支菜单必须在本地分支列表后提供“新建分支”，通过共享 Dialog 和自动聚焦的输入框收集 Trim 后名称；提交期间同步单飞并禁止关闭或重复操作，失败时保留输入并由根级 toast 展示 Git 原始错误，成功后使用 Server 返回的完整 Git 状态替换共享 Query 缓存、关闭 Dialog 并通过根级 toast 确认。聚合仓库模式继续只读展示，不提供分支切换或创建入口。
- 中栏 Composer 的模型与思考量必须使用一个统一紧凑触发器，选项只展示名称和尾部勾选，不展示 Provider 描述。桌面端使用两级菜单，移动端使用单层 Dialog 避免级联菜单越出视口；模型切换必须保留仍受支持的当前思考量，否则回落到目标模型默认值，不得保留独立原生下拉框。选择器必须支持键盘、Escape、外部点击和视口碰撞处理，并在工作台移动断点保持至少 `44px` 触控高度和 Composer 单行布局。
- Web 不提供登录路由或账号控件；Provider 资源不可用时展示 `codex login` 指引和 Query 重试操作，不调用账号接口。
- `shared/components/agent` 由项目完整维护 Agent 工作台复合组件源码；公开 Props 只服务真实调用方，样式、基础控件和本地化文案统一使用项目设计 Token，不保留外部组件库命名、registry 配置或兼容导出层。
- Task Timeline 与源码预览调用方必须通过轻量 `LazyMessageResponse` 边界加载 Markdown；加载期间完整展示保留换行的原文，重型 `MessageResponse`、Streamdown、Shiki 和语言 Grammar 不得静态进入调用方 Chunk。
- Task Timeline 的流式 Markdown 代码块必须限制在 Assistant 消息的可用宽度内，长代码不得让中栏会话容器产生横向滚动；Playwright 回归必须同时覆盖长代码渲染与代码复制，并断言会话容器的 `scrollWidth` 不超过 `clientWidth`。
- 通用 `Button`、`Input`、`Textarea`、`Tooltip`、`Dialog`、`DropdownMenu`、`ContextMenu` 和 `ButtonGroup` 必须复用 `shared/components/core` 的项目基础组件；Radix 只作为结构、行为和可访问性底层能力，`shared/components/core` 必须通过 `--ui-*` 驱动的 `brand`、`control`、`panel`、`foreground` 等项目 Token 提供完整默认视觉。Feature 的 `className` 只承担页面布局、定位和响应式尺寸；颜色、字号、字重、圆角、阴影及交互状态必须由项目组件默认值或显式 variant/size 提供。嵌入复合控件的输入必须使用显式 `embedded` 变体，checkbox、radio、hidden 等专用语义不得借用普通文本 `Input`。`tailwind-merge` 必须登记 `caption`、`meta`、`label`、`body-small`、`body`、`heading`、`title`、`display` 等项目 `text-*` 字号 Token，避免与文字颜色类冲突时误删排版。Dialog 必须保留 Portal、焦点圈定、Escape、backdrop 和关闭后焦点恢复；Tooltip 必须使用应用级 Provider 并限制在视口安全边距内；Dropdown Menu 与 Context Menu 的 Portal、视口碰撞、键盘导航、Escape、外部点击和焦点恢复必须交由 Radix 管理，Feature 不得重复实现坐标计算或全局事件监听。
- Button 内容默认居中；全宽导航、列表命令和侧栏入口必须显式使用 `contentAlign="start"` 保持左对齐，不能用只影响文字行盒的 `text-left` 代替 flex 主轴对齐。
- 父级已经持有 hover、selected 或 focus 表面的复合控件，其内部 Button 必须使用 `variant="embedded"` 和 `size="embedded"`，不得叠加默认 Button 的背景、阴影、固定高度或水平 padding；父级必须是该行唯一的交互表面。
- 所有 Button 内的 SVG 图标必须由共享 `Button` 尺寸契约统一约束，禁止依赖 Lucide 默认 `24px`。`icon-sm` 内图标固定为 `14px`，其他未显式覆盖的 Button 图标固定为 `16px`，触控目标放大不得同步放大图标；Button 必须统一设置 SVG 的 `shrink-0` 与 `pointer-events-none`。业务组件只在非 Button 图标或经设计明确的特殊尺寸下使用 `size-*`，Button 内图标不得重复声明常规尺寸。带图标的 link Button 必须保持单行 `inline-flex` 对齐，不得出现图标与文字拆行。
- Web 应用自有文案必须通过按功能拆分的 i18next 命名空间提供 `zh-CN` 与 `en` 资源，完整句子使用语义 key，数量和真实运行时值使用插值；用户消息、Assistant 输出、Command、Tool/Activity 原始名称、Plan 原文、路径、分支、文件名、Skill/MCP 名称、模型标识和服务端描述必须原样展示。Codex 设置英文术语以官方文档为准，不从中文反向翻译。
- Task Timeline 不展示原生 Reasoning Item 或 Chain of Thought；Codex Commentary 与 Final Answer 都作为普通 Assistant Message，通过 `MessageResponse` 展示。用户 Message 继续使用 Markdown，但必须保留原文中的单换行和缩进，树形文本与手工清单不得按 Markdown soft break 折叠；Assistant Message 继续遵循标准 Markdown 换行语义。只有当前运行 Turn 的最后一条 Assistant Message 使用 `streaming` 模式和动画，历史消息、已完成回复及非尾部回复统一使用 `static` 模式，避免重复执行流式 Markdown 解析。Command、Tool 等结构化 Item 保持独立可见，不包裹进思考容器。Turn 错误区域必须原样显示 Provider 返回的错误，不得添加“Turn 失败”或“连接失败”等本地标题和前缀。新聊天首次提交或已有 Task 启动新 Turn 时，提交开始后必须立即显示从用户动作起算的处理耗时和通用运行状态，不等待 `startTurn` 返回或 `turn.started`；HTTP 返回或权威 Turn 到达不能单独结束本地提交态，首个 Assistant Item 可见后才原子交接给 Turn。交接前的中间 Snapshot 即使暂时缺少该 Turn，或已将 Turn 标记为 `completed` 但尚未包含 Assistant Item，也不得清空计时和运行状态；只有 `failed` 或 `interrupted` 可以在 Assistant Item 出现前结束本地提交态，交接过程不得重复显示临时状态。运行中的 AI 回复必须在回复最后一行始终使用 项目 Agent 组件 `Shimmer` 表达持续生成状态。存在运行中的 Command、Tool、Activity 或流式 Plan 时，在“正在运行”后直接追加 Codex Item 的原始操作名称，其中 Command 同时显示终端图标，不得解析 `commandActions` 生成映射文案；快速操作已完成但 Turn 仍在运行时继续以 Shimmer 显示最近原始操作，不切换成完成文案，但后续 Assistant Message 开始流式输出后不得跨过该消息重复显示此前已完成的操作；没有结构化操作时回退为通用运行状态，并在 Turn 结束后移除。原始操作名称变化时只能更新 Shimmer 文本，必须保留同一 DOM 与动画时间轴，不得按文案长度改写扫光参数。
- 消息中的历史图片附件必须使用按钮缩略图在当前页面打开统一 项目 Dialog 预览，不得使用图片地址链接或新标签页；Dialog 必须提供图片名称、关闭按钮、Escape 和 backdrop 关闭行为，并保持完整图片可见。复制用户消息时只保留有序 Skill 引用与正文，不得复制图片、文件、粘贴文本等附件名称或占位文本。
- Task Timeline 的启动 Snapshot 与实时数据必须先归一化为 Task Store，再进入同一套 Store 渲染路径；不得维护直接遍历 Snapshot 的独立 Turn/Item 分组、组件结构或测试入口。
- Composer 使用 项目 Agent 组件 `PromptInput`、`Attachments` 和组合式工具栏，附件按钮必须以菜单分别提供“添加图片”和“添加文件”，并支持点击、拖放、粘贴、预览与移除；文件选择器覆盖官方 File Inputs 类型，图片选择器只列出 PNG、JPEG、WebP 与 GIF。文件单个及合计限制为 `50 MiB`，图片单张限制为 `10 MiB`、最多 `20` 张且合计限制为 `50 MiB`，生成的粘贴文本附件限制为 `1 MiB`；纯文本粘贴严格超过 1,000 个 Unicode 字符时生成名为 `Pasted text.txt` 的 `text/plain` 附件，不把全文写入编辑器，等于阈值和更短文本保持普通光标插入；草稿输入与附件选择是本地操作，在实时连接恢复期间仍保持可用，仅在正在提交时锁定，提交和设置等网络控件继续暂停；模型来自 Server Query，审批策略、审批审核方、沙盒模式、模型和思考量随同一个 Turn 请求提交，不保留禁用占位控件。
- Composer 附件菜单的“添加图片”和“添加文件”必须打开宿主 FileTree Dialog，通过 Client 从 CodeAgent 运行设备的主目录开始按展开节点读取支持的真实普通文件，不得调用隐藏的原生 `<input type="file">`；本地和 LAN 浏览器使用同一链路。确认后保存 Server 返回的受控 `AgentAttachment`，草稿、Task 切换和排队项必须直接保留该引用，实际发送时不得重复上传；浏览器拖拽和粘贴仍保存带 Blob URL 的浏览器文件，并沿用二进制上传链路。
- 宿主 FileTree Dialog 与左栏 Project 目录选择 Dialog 顶部必须复用同一文件系统工具栏，提供可提交的绝对目录路径输入并支持 Enter 和图标按钮导航；隐藏文件和目录默认不显示，显式开关必须用 `aria-pressed` 表达状态，并让当前目录及展开节点使用包含显示模式的独立 Query Key 重新读取。路径导航或隐藏模式切换必须清除旧选择，避免确认当前不可见目标。
- Composer 文本草稿必须在 Runtime 重渲染期间保留浏览器的 IME 组合缓冲，不能通过受控内容回写覆盖尚未触发 `input` 的临时文本；已有 Task 之间切换时必须复用同一个编辑区域 DOM 节点，并按 `projectId + taskId` 分别保存和恢复草稿、附件及 Skills，新聊天使用 Project 独立草稿；Task Snapshot 加载产生的 `connecting` 或 `reconnecting` 状态不得把该节点设为不可编辑，不能通过父级重挂载或短暂禁用破坏原生输入法上下文；程序化清空或替换草稿时仍需同步真实编辑区域，并使用 `compositionstart` 后触发重渲染及切换 Task 的 Playwright 用例覆盖中文首键。
- Composer 的纯文本粘贴必须作为浏览器可撤销的编辑操作写入 `contentEditable`，不得用绕过原生撤销栈的直接 DOM 插入代替；粘贴后必须支持 macOS 的 `Meta+Z` 和 Windows/Linux 的 `Ctrl+Z` 恢复上一状态，并使用真实浏览器 E2E 覆盖该行为。
- Composer 编辑器使用普通 `Enter` 提交，使用 `Shift+Enter`、macOS 的 `Meta+Enter` 或 Windows/Linux 的 `Ctrl+Enter` 插入换行；命令菜单只能消费未带换行修饰键的 `Enter`，输入法组合期间不得触发提交或命令选择。Safari 在候选确认时可能先触发 `compositionend`，随后发送 `isComposing: false` 且 `keyCode: 229` 的 `Enter`，Composer 必须继续将其识别为组合输入，并使用 Playwright 覆盖该事件序列。
- Composer 必须从当前 Task Snapshot 的用户消息提取输入历史；命令或文件菜单关闭时，`ArrowUp` 从最新记录向前浏览，`ArrowDown` 向后浏览并在越过最新记录后恢复进入历史前的未提交草稿。多行输入仅在光标位于首行或末行时进入对应方向的历史，选区、修饰键和输入法组合期间不得拦截原生方向键；菜单打开时方向键继续优先导航菜单。历史 Skill 名称匹配当前目录时恢复为 Token，已不可用的 Skill 保留为可见 `$name` 文本，历史附件不得被静默重新提交；使用真实浏览器 E2E 覆盖连续导航和草稿恢复。
- Composer 在已有 Task 中使用 Snapshot 携带的完整设置，在新聊天中按 Project 显式默认优先、Global 默认回退初始化完整设置；普通 Project 的沙盒选择紧邻审批并提供只读、工作区可写和完全访问，临时 Task 不显示该选择器且固定使用 `danger-full-access`；设置只由用户事件触发完整对象 Mutation，不得通过 effect 写回或从其他 Task 继承审批。

- Codex 子代理协作使用统一 `agent/*` Tool 数据；中间 Timeline 只用不可交互的 项目 Agent 组件 `Task` 展示操作名称、数量与聚合状态，不展示任务正文、模型或子线程 ID。右侧 Inspector 的“上下文”页签必须提供“子代理”栏目，按唯一子线程 Task ID 逐项展示 Codex `agentPath` 提供的昵称、模型、思考量和状态，不展示线程 ID或提示词；父回复完成后继续保留仍存在的子代理，只有明确的 `agent/close` 操作才移除对应项。有子代理的 Task 首次进入时优先展示该页签。单击栏目项打开可访问的统一 项目 Dialog，并按子线程 Task ID 挂载独立 Runtime，以 项目 Agent 组件 Timeline 展示 Snapshot 与流式 Item。关闭 Dialog 必须卸载 Runtime 并取消实时订阅，但不能中断 Codex 子代理；再次打开时重新读取最新 Snapshot checkpoint 并继续接收后续事件，不能只展示父协作 Item 的完成摘要。
- 右侧 Inspector 的“上下文”页签必须在“运行中的终端”栏目展示当前 Task 的后台终端命令与工作目录，并提供带可访问名称的停止图标按钮。终端可以晚于 AI 回复结束，Turn 完成不得移除该栏目；停止提交期间禁用操作，动作失败只通过根级 toast 报错，完整输出仍只在 Timeline 展示。
- 右侧 Inspector 的“上下文”页签必须使用包含 Project ID 与 Task ID 的 Task 级 Query，在“MCP”栏目展示当前 Task 可读取的 MCP 服务名称，并提供明确的加载、失败和无可读服务空态；没有当前 Task 时不得发起 MCP 请求。MCP Query 失败只能影响该栏目，不能让整个工作台进入 Runtime 不可用状态。不得保留旧“环境”栏目或展示模型、思考量、审批、沙盒、工作目录和 Git 分支。“来源”栏目对普通 Project 始终展示 Project 目录，并按首次出现顺序去重展示当前 Task 用户消息实际使用的 Skills 与附件；附件行必须复用现有文件分类，图片及不超过 `1 MiB` 的源码、文本在当前页面 Dialog 预览，Office、PDF、归档及超过预览上限的文件通过受控 Task Mutation 交给宿主系统默认应用，不得渲染下载入口或向 Web 暴露宿主路径；最新计划必须位于上下文内容最底部，并使用与其他栏目一致的无卡片容器样式。临时 Task 的 Inspector 必须直接渲染上下文内容、不显示 Tab，且不得展示内部 Project 目录。不得展示 `This Mac`、硬编码分支、演示来源或未接通的“添加来源”操作。
- Task Timeline 的用户消息和 AI 回复末尾都必须常显可访问的复制操作与本地时间；每个有开始时间的 AI 回复在首个回复区域常显当前语言的处理耗时，运行态按秒递增并展示全部 `commentary` 与结构化操作，终态使用 `completedAt - startedAt` 固定显示并停止计时。存在 `final_answer` 的终态 Turn 必须默认隐藏最终回复之前的明确 `commentary` 与结构化操作，只保留最终回复、文件变更摘要和消息操作；耗时栏改为带可访问名称和 `aria-expanded` 的按钮，允许展开并再次收起中间过程。缺少阶段的历史 Assistant Message 不得被推断为 `commentary`。消息 Item 和相邻 Turn 之间保留明确纵向间距，不能让下一条用户消息贴住上一条回复。统一 `review` Item 按用户请求位置只显示一条当前界面语言的固定文案、复制操作和 Review 模式标签，不得展示 Codex 内部英文 Review Prompt 或重复时间。
- Task Timeline 的用户消息必须按协议顺序渲染统一消息字段携带的多个 Skill Token；实时 Turn、首轮乐观消息和重新打开 Task 后的历史消息复用编辑器 Token 的 `brand` 主色模块。Web 不从普通文本猜测 Skill，Provider 必须解析 Codex `userMessage.content` 中的 `skill` 字段并在丢弃原生路径后提供 Skill 名称。
- Task Timeline 的用户消息必须渲染统一消息协议携带的附件：图片提供可访问的缩略图查看入口，粘贴文本使用 项目 Agent 组件 紧凑文件卡片并提供受控下载入口；附件作为独立于用户文本气泡的块按协议顺序显示在气泡上方，纯附件消息不得渲染空文本气泡。提交响应尚无权威用户 Item 时使用上传响应元数据即时回显，权威 Item 到达后原子接管。Web 只使用随机附件 ID 构造 Project/Task 作用域受控端点，不接收 Base64 Data URL、附件正文或 Codex 本地文件路径。历史图片固定使用 `loading="lazy"`、`decoding="async"` 和显式 `width`/`height`；Timeline 使用 `@tanstack/react-virtual` 按稳定 Turn ID 动态测高并限制挂载窗口，不得在 Item 层重复虚拟化或恢复旧 `content-visibility` 逻辑。
- Task Timeline 默认随 AI 流式内容自动滚动到最新位置；Turn Virtualizer 使用 end anchoring 保持流式测高稳定，用户主动离开底部后暂停跟随，用户再次滚动到底部或使用“回到底部”操作后恢复自动跟随；每次切换 Task 都必须等待消息分帧布局稳定后，将中栏聊天消息区域直接滚动到最底部，不恢复离开前的滚动位置。
- AI 回复中的 Project 相对或绝对文件引用必须按格式分流：代码与文本打开只读源文件 Dialog，带行号时定位并高亮对应行；GIF、JPEG、PNG、WebP 打开当前页面的图片 Dialog；Office、演示、表格和归档等不可预览格式调用 `system-default`，不得先展示源文件错误。源文件与图片只通过 Server 受控接口读取，页面不得直接访问本地文件系统。Markdown 与 MDX 源文件的顶部必须提供带可访问名称的图标按钮，在渲染视图和带行号原文之间切换；切换文件或关闭弹窗后必须恢复原文视图。外部 `http`、`https` 链接固定使用新标签页和 `noopener noreferrer`，危险协议不得生成可点击链接。
- Timeline 展示 Task Snapshot 中的 Agent 文件操作；Inspector 的“变更”页签只在当前 Project 存在真实 Git 未提交变更时渲染变更总览，工作区干净时整个总览和操作区都不渲染。总览左侧在“未提交变更”下方依次同行展示变更总数、增加行数和删除行数，右侧只展示中性背景的“提交”按钮；增删行数只在总览展示，并在页签可见时按当前轻量状态的 `snapshot` 请求详细状态计算，Project 文件树不得重复展示文件或目录变更统计。文件审核继续通过 Timeline 的变更卡片进入统一文件审核 Dialog。“提交”从右侧打开统一 项目 Sheet，顶部依次提供直属子 Git 项目选择、当前分支、message 生成与编辑，以及 commit/commit+push 分段操作；中部使用 项目 Agent 组件 `FileTree` 按 staged 与 unstaged 分组展示 Project 相对路径，目录默认展开，同一路径的重复状态必须共享选择结果；底部使用当前所选 Git 项目和分支的分页历史记录，并明确展示加载、错误和空状态。提交控制器、Sheet 和 Mutation observer 只在首次打开时动态加载并注册，关闭后必须整体卸载；320px 窄屏不得产生水平溢出。聚合直属子仓库模式打开时默认选择排序后的第一个 Git 项目；切换 Git 项目必须保持 Sheet、标题和仓库选择器持续挂载，只更新下方提交内容，并清空旧文件选择、message 和 Mutation 状态。生成 message、commit 与 commit+push 只能携带同一仓库的相对路径和 `snapshot`；commit 或 commit+push 完整成功后必须立即关闭 Sheet，并通过应用根级的可访问 toast 宿主提示对应成功结果，通知在页面顶部居中显示、自动消失且不提供关闭按钮，通知生命周期不得依附于按需提交抽屉；commit 成功但 push 失败或未配置上游时，Sheet 必须保留 commit SHA 与部分成功状态。提交完成后必须失效当前 Git 项目的状态与历史 Query。总览下方使用本地 项目 Agent 组件 `FileTree` 展示受限 Project 文件树，“项目文件”标题必须固定在文件树滚动容器之外；目录默认折叠，用户展开时才加载其直接子项，折叠父目录时清理后代展开状态；点击存在 Git 变更的文件必须打开单文件 Diff 弹窗，点击未变更文件复用 AI Markdown 文件引用分流：源码与文档打开受控源文件 Dialog，图片打开当前页面的图片 Dialog，不可预览格式调用 `system-default`；根目录和各级子目录的加载、空与错误状态必须明确。Inspector 只消费 Project Git Query 并提供手动刷新；运行期刷新、终态刷新、失败退避重试和成功恢复由 Project Runtime 的单一 Git 状态协调器负责。完整 Diff Viewer 使用 `@pierre/diffs/react` 并仅在打开弹窗后动态加载，不保留旧 Git 分组列表或演示数据。
- 提交 Sheet 必须固定在动态视口高度内且自身不得滚动；标题区只显示提交标题，提交信息输入框上方不得渲染标题或分支栏目，当前分支显示在当前分支历史标题最右侧。提交信息必须保留换行内容，但输入区域固定为一行可视高度并允许内部纵向滚动；生成 message 使用输入框最右侧的纯图标按钮，并通过 Tooltip 提供完整操作名称。变更与当前分支历史作为默认展开、可独立收起的紧凑区域共享剩余高度，长内容只能在各自区域内部滚动；staged 或 unstaged 没有文件时不得渲染对应分类。变更文件树中没有直接文件且只有一个子目录的连续目录链必须与连续审核树一致，合并为单一路径节点；文件复选框位于文件名左侧，单击文件行打开统一单文件 Diff，只有操作复选框才能改变提交选择；文件名与状态图标按新增、修改、删除分别使用成功、警告、危险语义色。历史区域标题只保留折叠箭头、文字和最右侧的当前分支，不显示额外历史图标，也不得在内容顶部重复渲染“当前分支：xxx”说明；历史 commit 必须可点击并按需打开与 Git 历史入口共用的独立审核 Dialog，审核期间提交 Sheet 保持挂载且暂时退出可访问树，关闭审核后恢复原表单、文件选择和历史滚动状态。桌面和 `320px` 窄屏都必须验证无整体纵向滚动、无横向溢出及折叠后的高度重新分配。
- 运行中的 Turn 每当 `file_change` Item 进入 `completed`，必须立即逐文件展示文件名、增删行统计和可点击的单文件 Diff 入口；Turn Diff 流式更新期间的折叠提示必须订阅当前 Turn 最新且仍处于 `pending | running` 的 `file_change` Item，优先显示文件名和增删行统计，仅在尚无文件级事件时回退为通用实时变更文案。该 Item 进入任一终态后必须立即隐藏实时提示，不能与已完成文件行重复展示。Turn 结束后改为在回复末尾聚合全部已完成文件变更，以卡片展示去重文件数和总增删行，不能同时保留运行态条目造成重复。单击文件继续打开单文件 Diff，“审核”则打开同一组文件的连续审核弹窗。连续审核必须提供明确的当前位置、上一个/下一个按钮、左右方向键和首尾禁用状态，并支持 Escape 与 backdrop 关闭。连续审核右栏必须按 Project 相对路径使用本地 `FileTree` 展示变更文件；没有直接文件且只有一个子目录的连续目录链合并为单一路径节点，文件节点保留增删统计和当前选中状态。变更文件导航在桌面端打开弹窗时默认展开，在工作台移动断点下默认收起，两端均通过可访问图标按钮展开或收起；移动端展开时从右侧覆盖审核内容，不得压缩 Diff 宽度。单文件 Diff 与连续审核弹窗的根网格不得被 Diff 固有宽度撑出视口。
- 交互控件使用语义化元素并提供可访问名称、键盘行为和明确状态。
- Approval 使用 `Confirmation` 提供 Allow、Deny 和可用的 Session 级决策；进入已有待审批 Task 或当前 Task 新增审批时，队首可操作请求的“允许”按钮必须自动聚焦，让用户可直接按 Enter 确认；网络审批必须明确显示目标 Host 与协议，不能依赖命令文本表达授权对象；User Input 的选择、确认和短文本分别使用 Radio、可切换 Button 和 Input，提交回答使用主色按钮，提交开始后立即禁用重复操作，响应确认后在同一 Turn 中显示用户回答。
- 可能位于裁剪容器或视口边缘的 Tooltip 必须脱离局部层叠上下文渲染，并在桌面与窄屏中自动翻转、限制到视口安全边距；同时验证 Hover 和键盘焦点行为。
- `shared/styles/globals.css` 是颜色、字体、间距、圆角、阴影、动效和固定布局尺寸的唯一设计 Token 来源；组件使用语义化 Tailwind Token，不散落视觉字面值。
- 浅色与深色主题在同一语义 Token 中使用 `light-dark()` 定义，`data-theme` 只切换 `color-scheme`，禁止复制整套主题变量。
- 颜色模式只提供 `light` 与 `dark`，使用版本化浏览器存储保存并在 React 挂载前同步到根节点；主题切换即时生效，不进入 Agent 设置 API，也不因取消设置表单而回滚。
- 界面语言只提供 BCP 47 标签 `zh-CN` 与 `en`，默认和生产回退为 `zh-CN`；使用独立版本化浏览器存储保存，在 React 挂载前初始化并同步 `<html lang>`。语言切换即时生效，不进入 Agent 设置 API，也不因取消设置表单而回滚。
- 主题色固定为浅色 `surface #ffffff`、`ink #111111`、`brand #006aff`、`diffAdded #28a948`、`diffRemoved #eb001d`，深色 `surface #181818`、`ink #ffffff`、`brand #339cff`、`diffAdded #40c977`、`diffRemoved #fa423e`；Skill 展示统一复用 `brand`，不维护独立颜色；浅色大面积区域保持纯白，普通文字使用 `450` 字重，不添加固定浅灰底。
- 工作台区域优先使用材质背景、淡阴影和留白区分层级，不使用贯穿面板的高对比边框；视口进入覆盖模式时关闭已打开的桌面面板。左右栏的打开状态仅由各自工具栏按钮、窄屏遮罩或响应式视口变化控制，任何情况下都不得由 Escape 键关闭。桌面常驻布局必须提供可拖拽且支持方向键的语义化分隔线，左栏宽度限制为 `220px` 至 `400px`，右栏限制为 `260px` 至 `480px`；窄屏覆盖模式不显示分隔线。
- 永久 Sidebar 和 Inspector 使用连续同色背景，仅在其纵向边界添加低对比单像素分隔；三栏标题行使用相同高度并保持文字、图标垂直居中，侧栏顶栏不与下方内容分隔，主内容 Toolbar 的单像素底部分隔与左栏搜索框、右栏 Tab 的顶部对齐。不使用模糊或多层重阴影，浮动阴影只用于 Composer、弹层和独立表面。
- 视觉系统变更使用 Playwright 检查 computed style、桌面与移动溢出、窗口缩放和控制台错误。
- 项目组件只能在 `shared/components/core` 或 `shared/components/agent` 内直接维护源码，并同步更新行为、可访问性与视觉测试；禁止重新引入外部 registry、preset、组件生成配置或旧目录兼容层。
- 只有形成稳定复用模式后才写入本规范。
