# CodeAgent 2.0 Beta 发布闭环设计

## Goal

将当前 `feat/tauri` 通过受保护 PR 合入 `main`，为 Desktop 增加真正经过 Tauri IPC 的 E2E 门禁，并以 `v2.0.0-beta.1` 完成一次 draft-first 的三平台 Preview / Unsigned 发布。只有 macOS 14 Apple Silicon、Ubuntu 22.04 x64、Windows 10 x64 smoke 与受保护 Updater 验收全部通过后，才向 npm `beta` dist-tag 发布并公开 GitHub Release。

## Suggested Spec Reads

- `.superwork/spec/guides/index.md`：版本单一来源、三平台发布矩阵、Updater 签名和完整门禁。
- `.superwork/spec/frontend/quality-guidelines.md`：Desktop Transport 与宿主构建测试约束。
- `.superwork/spec/shared/quality-guidelines.md`：跨 IPC 契约、错误和文件规模要求。
- `docs/tauri-migration-plan.md`：Phase 9、真实 Desktop E2E 和 clean VM 完成定义。
- `docs/releasing.md`：当前 tag、draft、npm 与人工审批流程。

## Existing Context

- 根版本与 CLI、三个 native packages、Cargo workspace 当前均为 `1.10.0`；根 `package.json` 是唯一产品版本源。
- `.github/workflows/release.yml` 已能创建 draft、构建三个目标、执行 hosted macOS/Linux smoke，并等待带 `windows-10` 标签的 self-hosted runner。
- 仓库只有 Vitest `mockIPC`、Rust command test 与 workflow 静态契约，没有启动真实 Tauri binary 的 WebDriver E2E。
- GitHub `main` 未保护、无 ruleset、无 `release` Environment、无 self-hosted runner；仅存在 `TAURI_SIGNING_PRIVATE_KEY` Secret。
- GitHub `v1.10.0` 及更早版本没有 Desktop updater 安装基线，因此首个 Desktop 版本无法诚实执行“从上一正式 Desktop 原地升级”。
- Updater 当前使用 `/releases/latest/download/latest.json`；GitHub latest API 排除 prerelease。为保持 Beta Updater 可发现，本次 GitHub Release 使用 beta SemVer 和 Beta 标题，但保持 `prerelease=false`；npm 仍严格发布到 `beta` dist-tag，不移动 `latest`。

## Considered Approaches

### A. Embedded WebDriver + 单一受保护发布工作流（采用）

通过仅在 Desktop E2E profile 启用的 `tauri-plugin-wdio-webdriver`/`tauri-plugin-wdio` 启动真实 binary，使用 `@wdio/tauri-service` 执行 IPC 往返。PR 合并、tag draft、三端 smoke、Updater 验收、npm beta 发布和 Release promotion 保持一条可审计依赖链。

优点是 macOS、Windows、Linux 使用同一驱动模型，且真实进入 Tauri command；缺点是需要维护测试专用 Rust feature，并增加 macOS PR job 构建时间。

### B. 外部 `tauri-driver`

不向测试 binary 注入 embedded driver，由系统 WebDriver 驱动。实现更接近旧 Tauri 流程，但 macOS 没有原生 WKWebView WebDriver，无法形成三端一致入口，因此不采用。

### C. 仅保留安装启动 smoke 与 `mockIPC`

依赖最少，但不能证明 Renderer 到 Rust command 的真实 IPC，也不能满足项目 Phase 9 定义，因此不采用。

## Recommended Approach

### 真实 Desktop IPC E2E

- 在 Desktop crate 添加默认关闭的 `desktop-e2e` feature；只有该 feature 注册 embedded WebDriver 和 WDIO backend plugin，正式 release binary 不包含测试服务。
- 新增独立 `tests/desktop-ipc` WebdriverIO 配置与一个短 happy-path：启动 production frontend 的 Desktop debug binary，经页面 host client 调用 `access_status`/`app_diagnostics`，断言 UI 已完成 Desktop composition 且 `browser.tauri.execute()` 能从 Rust 返回稳定值。
- 测试使用独立临时 `HOME`、`CODEX_HOME` 与数据目录，关闭后等待受管 Runtime/Codex/SQLite 清理；不复刻现有浏览器业务 E2E。
- CI 在 `macos-14` 增加 `Desktop IPC E2E` required check。release 三端安装 smoke 继续验证实际分发包，测试插件不得进入正式 bundle。

### PR 与 main 保护

- 将实现推送到 `feat/tauri`，创建面向 `main` 的非 draft PR。
- 保护 `main`：强制 PR、管理员同样受约束、禁止 force push/delete、要求线性历史与 conversation resolution。
- Required checks 使用仓库实际 check 名称：Ubuntu/Windows Quality、Ubuntu/Windows Web E2E、macOS smoke、Desktop IPC E2E。
- 个人仓库不设置大于 0 的 required approval 数，否则作者无法自行完成发布 PR；代码审查仍可自愿进行。

### Windows 10 runner 与 release Environment

- workflow 固定使用 `[self-hosted, Windows, X64, windows-10]`，不允许 fallback 到 `windows-2022`。
- 仓库添加 Windows runner bootstrap/校验脚本，只接受显式 runner registration token，并在注册后核对 OS、arch、labels 与在线状态。
- runner 必须来自真实 Windows 10 x64 主机并在 job 前恢复干净快照。当前 GitHub 无 runner，缺少该主机时 release workflow 只能保持 queued，不得跳过。
- 通过 GitHub API 创建 `release` Environment，以仓库所有者为 required reviewer，关闭管理员绕过，并只允许 `v*.*.*` tag deployment。

### 首发 Updater 验收

- 自动 `updater-acceptance` job 在 draft 生成后下载 `latest.json`、三个目标 updater artifact 与 `.sig`，验证版本、URL、平台覆盖、内置公钥签名，并对每个平台执行 artifact 字节篡改和签名篡改拒绝测试。
- 首个 Desktop 发布明确进入 `bootstrap` 模式：没有上一公开 Desktop 安装基线时，不声称完成原地升级；以上密码学与 metadata 验收、真实 IPC、三端安装启动 smoke 共同构成首发闭环。
- 后续版本检测到上一公开 Release 含完整 Desktop updater metadata 后，自动切换 `upgrade` 模式，并要求在三端从上一版本安装、发现、下载、安装、重启到目标版本。
- `release-approval` 依赖自动 Updater 验收和三端 smoke，Environment reviewer 只确认自动证据，不再用一句 `echo` 代替验收。

### Beta 版本与发布

- 版本统一更新为 `2.0.0-beta.1`，tag 为 `v2.0.0-beta.1`。
- `CHANGELOG.md` 新增带日期的 Beta 条目并更新 compare links；发布说明明确 Desktop Preview / Unsigned、最低系统和首发 Updater bootstrap 边界。
- npm native packages 与主 CLI 均使用 `npm publish --tag beta`，并在发布后验证 `beta=2.0.0-beta.1` 且 `latest` 未改变。
- GitHub Release 标题包含 `Beta` 与 `Desktop: Preview / Unsigned`。为让现有 `/releases/latest/` Updater endpoint 可发现该版本，本次 Release 保持 `prerelease=false`；版本本身仍是 SemVer prerelease，不能被误发布到 npm `latest`。
- tag push 只创建 draft。全部自动门禁和受保护审批通过后，publish job 才上传 checksums、发布 npm beta 并公开 Release。

## Component Responsibilities And Interfaces

- `apps/desktop/src-tauri/*`：按 feature 注册测试 WebDriver plugin；生产 command、capability 与 updater 行为保持不变。
- `tests/desktop-ipc/*`：定位测试 binary、启动 WDIO、验证真实 IPC 和有界清理。
- `.github/workflows/ci.yml`：提供可作为 branch protection required check 的 Desktop IPC E2E job。
- `.github/workflows/release.yml`：计算 release channel、执行 Updater 自动验收、按 `beta` dist-tag 发布并在末端 promotion。
- `tools/release/*`：校验 updater metadata/signature/tamper、runner prerequisites 和发布 channel；脚本保持跨平台输入显式且有界。
- GitHub branch protection、Environment、runner：分别控制合入、人工 release gate 与 Windows 10 最低系统证据。

## Error Handling

- Desktop IPC E2E binary、driver、IPC 或清理超时均使 required check 失败；不回退到 `mockIPC`。
- 缺少 Windows 10 runner 时 release 保持 queued；不得修改 labels 或临时改 hosted runner 放行。
- `latest.json` 缺平台、版本不一致、签名验证失败或篡改未被拒绝时 Release 保持 draft，npm 不发布。
- Environment 未审批时 publish job 保持 waiting。
- npm 某 native package 已存在时只接受同版本幂等跳过；发布后 dist-tag 不符合预期时不 promotion GitHub Release。
- tag、manifest 或 CHANGELOG 不一致时在 build 前失败。

## Verification Strategy

- 本地：targeted Desktop IPC 配置测试、`pnpm check`、`pnpm check:rust`、`pnpm check:ci`、`pnpm test:e2e`、版本/包/Desktop artifact 检查。
- PR：required checks 全绿，确认测试 WebDriver plugin 不在正式 release feature/bundle 中。
- GitHub 配置：回读 branch protection、Environment reviewer/tag policy、runner labels/status 和 Secret 名称。
- Tag：确认 Release 为 draft；macOS 14、Ubuntu 22.04、Windows 10 smoke 成功；Updater bootstrap 自动验收成功；Environment 审批后 npm `beta` 与公开 Release 状态正确。

## Non-Goals

- 不添加操作系统代码签名、公证、商店分发或新平台架构。
- 不用 Windows Server 冒充 Windows 10 产品验收。
- 不把真实 Tauri E2E 扩展为完整 UI 回归套件。
- 不把 `2.0.0-beta.1` 设置为 npm `latest`。
- 不伪造从不存在的上一 Desktop 正式版本升级证据。

## Success Criteria

- PR 合入前真实 Desktop IPC required check 与现有 CI checks 全绿，`main` 已保护。
- `release` Environment 有 required reviewer、禁止管理员绕过且只允许版本 tag。
- Windows 10 x64 self-hosted runner 在线并带精确标签，三端 smoke 使用当前 tag artifacts。
- Updater 自动验收验证三平台 metadata、合法签名和篡改拒绝；首发明确记录 bootstrap 模式。
- `v2.0.0-beta.1` draft 经全部门禁后公开，npm `beta` 指向 `2.0.0-beta.1`、npm `latest` 保持原稳定版。
- `CHANGELOG.md`、Release、npm、Desktop metadata 与所有 manifest 版本一致。
